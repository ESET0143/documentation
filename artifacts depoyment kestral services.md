## ASP.NET Core Deployment Quick Notes

### 1. `dotnet restore`

* Downloads NuGet packages required by the project.

```bash
dotnet restore
```

---

### 2. `dotnet build`

* Compiles source code (`.cs` files).
* Creates DLL files in the `bin` folder.

```bash
dotnet build
```

Output:

```text
bin/Debug/net8.0/
 └── MyApp.dll
```

---

### 3. `dotnet run`

* Builds the project (if needed).
* Runs the application.
* Starts the Kestrel web server.

```bash
dotnet run
```

Equivalent to:

```bash
dotnet build
dotnet MyApp.dll
```

---

### 4. Kestrel

* Default web server for ASP.NET Core.
* Serves HTTP/HTTPS requests.
* Starts when the application runs.

```text
MyApp.dll
   ↓
dotnet
   ↓
Kestrel
   ↓
Port 5000/5001
```

---

### 5. `dotnet publish`

* Creates production-ready files.
* Output folder is used for deployment.

```bash
dotnet publish -c Release
```

Output:

```text
publish/
 ├── MyApp.dll
 ├── appsettings.json
 └── ...
```

---

### 6. Artifact

* Deployable package generated by CI/CD pipeline.
* Usually contains published application files.

```text
Code
 ↓
Build
 ↓
Publish
 ↓
Artifact (ZIP)
```

---

### 7. Linux Service (systemd)

Service file example:

```ini
[Service]
ExecStart=/usr/bin/dotnet /opt/myapp/MyApp.dll
```

Start service:

```bash
sudo systemctl start myapp
```

Check status:

```bash
sudo systemctl status myapp
```

Restart service:

```bash
sudo systemctl restart myapp
```

---

### 8. Deployment Flow

```text
Git Push
   ↓
Azure DevOps Pipeline
   ↓
dotnet restore
   ↓
dotnet build
   ↓
dotnet publish
   ↓
Artifact
   ↓
Copy to Linux Server
   ↓
Restart Service
   ↓
Kestrel Starts
```

---

### Interview One-Liner

**Artifact = Published output of an application used for deployment.**

**Kestrel = ASP.NET Core web server that runs the application and serves requests.**

**Linux service (systemd) runs `dotnet MyApp.dll`, which starts Kestrel in the background.**
